# Manual desktop acceptance — required before claiming functional interception

Automated tests cannot prove real GNOME/KDE launcher behavior or Claude's hook semantics. Run this checklist separately on Ubuntu GNOME and Debian/KDE (and each additional environment you intend to support). Record date, OS, session type (X11/Wayland), desktop version, Desktop package version, standalone Code version, bundled/local-session engine version, guard revision and each result. Currently these real-app checks are **not verified** by this repository's headless test results.

The GB/non-GB scenarios below assume the default policy. Repeat with another selected country to verify configuration changes. Use a disposable user account. Back up its Claude settings. Have legitimate GB and non-GB routed connectivity available; keep IPv4 and IPv6 visible. Do not change provider constants or add production allow overrides for testing.

- [ ] Save preinstallation desktop entry, user override, custom hooks, shell configuration and MIME associations.
- [ ] Run dry-run; confirm expected source and target entries, every installation and autostart entry.
- [ ] Install twice; confirm no duplicate PATH blocks or hooks and an active systemd user monitor.
- [ ] Search **Claude** in Applications; confirm name, icon, categories and existing favorite/pin remain usable.
- [ ] On GB connectivity, launch from search; confirm the original app opens and a normal Desktop Chat works.
- [ ] On non-GB connectivity, launch from search; confirm denial, including with an existing Desktop process present. Confirm a visible error window names the allowed and detected countries and ifconfig.io, and Claude stays closed after dismissing it. Test Zenity on GNOME and KDialog on KDE. Stop the monitor and verify a guarded launch starts it again. If startup fails or the provider is unavailable, verify the launcher shows the reason. In an isolated account without a dialog helper, confirm notification/stderr fallback and continued denial.
- [ ] Check the dialog in light/dark themes and with enlarged system text: heading, country facts and recovery step should remain readable without clipping. Tab between labeled buttons, open Show details (or KDE’s expandable Details), then dismiss with Close/Escape/window close. Confirm the technical reason and diagnostic command appear only in details, no button retries or opens Claude, and an unknown country is shown as Not verified rather than a mismatch. Verify screen-reader reading order and button announcements in the actual desktop session.
- [ ] Exercise each desktop action, supported URL/file association, pinned item, autostart, desktop shortcut and D-Bus activation path. Record which use Exec and which bypass it. Independent direct D-Bus/hotkey paths are not guaranteed.
- [ ] Open a local Desktop Code session; inspect its engine version and `/hooks` list. Confirm user settings are actually shared.
- [ ] On GB, submit a prompt, invoke a prompt-type slash command/skill (expansion), and request a harmless tool. Confirm all three hooks execute; test existing custom hooks in the same sessions.
- [ ] On non-GB, confirm each of those operations is blocked **by the hook**, independently of the launch wrapper. Use an already-open CLI session or isolated hook acceptance account so Desktop termination does not mask missing hook execution.
- [ ] In a disposable account only, temporarily change the guard hook command to a missing executable, then a deliberately failing/invalid-output command, then a command exceeding 30 seconds. Confirm each event blocks on failure/timeout. Restore the exact owned group before uninstalling. Never do this in production settings.
- [ ] On GB, open Desktop Chat and local Code. Change to non-GB while running. Measure check and grace delays; confirm SIGTERM then forced termination when needed, runtime error window and journal reason. Leave the window open and verify another protected launch is still monitored; confirm repeated failures do not create a stack of windows. Open Details and check the log command. Restart/stop the service with a window open and verify the helper closes cleanly. Requests before detection are possible and are not a test failure.
- [ ] Disconnect entirely and simulate provider/DNS/TLS failure with an isolated test network. Confirm denial and closure; reconnect to GB and confirm a deliberate fresh launch works. The guard must not restart Claude automatically.
- [ ] Test GB IPv4/non-GB IPv6 and the reverse, then true IPv4-only and IPv6-only connections. Confirm every available family must verify GB.
- [ ] Restart the monitor while Desktop runs. Verify processes are rediscovered. Test child processes, app exits during checks, and unrelated programs with Claude-like names: unrelated processes must remain alive.
- [ ] Verify Bash and Zsh `type -a claude`, argument forwarding, exit status, Ctrl-C, and command-cache behavior. Test a shell with a custom login profile.
- [ ] Update Desktop through its package manager; run doctor and reinstall. Verify source executable/path changes and preserved custom metadata.
- [ ] Add a new preference/custom hook after installation, then uninstall. Confirm it survives; original desktop, CLI, URL associations and original custom hooks work. Open a new shell to clear old PATH state.
- [ ] Install with `--country` set to a nondefault country; verify CLI, Desktop and hooks use it. Change it with `set-country` while the monitor runs and verify the next check uses the new value without a restart. Reinstall without `--country` and confirm it retains the selection.
- [ ] Set `--timezone Europe/London`, fully quit and relaunch Desktop and CLI, then verify application timezone behavior (including local Code subprocesses). Change it with `set-timezone` and confirm it requires a new process. Verify `inherit` restores normal behavior and the system timezone is unchanged.
- [ ] Edit config.json while monitoring: verify country, interval and grace apply on subsequent checks, malformed saves deny, and repairing the file resumes valid checks. Test optional allowed_ips with matching/nonmatching IPv4 and IPv6. Verify returned IPs appear beside countries on success and failure, and unavailable results are labeled honestly. Check that success_notifications true/false affects only guarded Desktop launch confirmations, runtime successes/recovery remain silent, and the success popup closes on OK or after five seconds while Claude opens immediately.
- [ ] Re-run uninstall; confirm it is harmless. Confirm backups remain.

For remote/SSH/cloud sessions, record them as **unsupported/unverified** unless you separately establish where hooks run, their engine compatibility and which egress they measure. A remote check is not a laptop location check. Do not promote an installed file or service-active result to a functional acceptance result.
